# app-with-postgres: get a database with one declaration (`services:`)

English | [繁體中文](README.zh-TW.md)

The dependency declaration in this example is just four lines:

```yaml
services:
  db:
    type: postgres
```

The image, port, data volume, bootstrap environment variables, and health check all come from defaults tied to `type`.
After deployment there are **two** components:

```
$ qooq component ls
NAME                   IMAGE                       PHASE
app-with-postgres-db   postgres:16-alpine          Running
app-with-postgres      app-with-postgres:<sha7>    Running
```

`app-with-postgres-db` is an **ordinary component**, not a black box: `qooq component logs/get/stop/rollback`
all work on it, and you can also deploy a database yourself and join it to the same network without using `services:`.

## What the app gets

These environment variables exist without you writing anything (the service name `db` gives the prefix `DB`):

```
DB_HOST=app-with-postgres-db   DB_PORT=5432   DB_USER=app_with_postgres
DB_PASSWORD=<auto-generated>   DB_DATABASE=app_with_postgres
DB_SCHEME=postgres             DB_URL=postgres://…
DATABASE_URL=postgres://…      # extra, conventional name provided when the service is named db
```

When your framework expects a different variable name, point it yourself with interpolation (this is how `MYAPP_DB_DSN` in this example comes about):

```yaml
run:
  env:
    MYAPP_DB_DSN: "postgres://${service.db.user}:${service.db.password}@${service.db.host}:${service.db.port}/${service.db.database}?sslmode=disable"
```

`GET /` prints the connection info injected by qooq (password masked), and `GET /healthz` returns 503 when no database was obtained.

## Three details you do not have to handle

- **The service starts first and is confirmed ready before the app is deployed** (waits up to 3 minutes), so an app that connects to the DB at startup does not hit an empty socket.
- **The password is generated once and then fixed.** The password is written into the data directory when the database is initialized; changing it later would make the app unable to open its own data.
  So it is stored on the target (encrypted when `secret.key` is set) and reused on every deployment.
- **Redeploying after changing the app's code does not restart the database**: if the service spec has not changed, it is left completely alone.

## How to run (local demo)

```bash
qooqd -listen 127.0.0.1:7777 -data /tmp/qooq/qooq.db &
QOOQ_WATCHER_MOUNTS_DIR=/tmp/qooq/mounts qooq-watcher &

qooq watch add --name app-with-postgres \
  --repo file:///tmp/qooq/app-with-postgres.git --component app-with-postgres --poll 30

curl $(qooq component get app-with-postgres | awk '/endpoints:/{print $2}')   # shows the injected connection info
qooq component logs app-with-postgres-db --tail 20
```

To connect from the host with `psql`, publish the service's port:

```yaml
services:
  db:
    type: postgres
    ports: ["15432:5432"]
```
